## What's new in Sentora-2027.94

- Elk node: `sentora-elk-node dashboard install FILE.ndjson|https://... [NAME]`, `dashboard list`, `dashboard remove NAME`: adds a dashboard someone made (a Kibana export) to the node's Kibana with one command. The file is checked first: only dashboards and what they show (visualizations, Lens, maps, saved searches, data views, tags, Canvas), never connectors, alerting rules or anything else that acts or sends data out; Sentora's own dashboards (ids sentora-...) can not be replaced; at most 20 MB; addresses over https only. What each file added is kept (root only) in /etc/sentora-elk/dashboards/, so remove takes away exactly that; the update keeps added dashboards.
- zGod 101 and Log Forwarder 214: zGod writes its figures for the Elk node into the panel's log folder (`zgod.log`, 640, under 5 MB): each account's disk, bandwidth, quotas, websites, mailboxes, databases and FTP once an hour, the server's totals, and every suspend and mailbox switch (who, by whom, why; a mailbox by its account, never its address; no email addresses). Log Forwarder sends it with the panel's logs (The panel), and the Elk node reads it (kind `zgod`, numbers as numbers into `sentora.zgod.*`) for its new **zGod** dashboard: accounts, suspended, resellers, disk and bandwidth, the accounts nearest their quotas, the biggest users, accounts by reseller and package, what zGod did and why. A node updated from before moves its logs on to a part with the new fields (lazy rollover).
- zGod 101: a top-down look at the whole panel, as the old zGod was: new tabs **Usage** (every account's disk and bandwidth against its quota and its share of the server's), **Domains** (every domain, subdomain and parked domain with its account, reseller and state), **Mail** (every mailbox, forwarder, alias and distribution list), **MySQL** (every database with its size and users; every MySQL user with where from and its databases, never a password), **FTP**, **Cron jobs**, **Docker apps** (when Docker Hosting is on the panel: every app's state, size, disk used and node) and **Packages** (owner, quotas, accounts using it); plain tables with a search, on a phone each row a small card. Each account shows its activity (logged in recently: 7 days, active: 90 days, inactive, never) and its last login with how long ago; the Accounts filter has them too. An account's page adds its MySQL users, its DNS records by domain and its Docker apps, a **Shadow** button (the panel's own Shadowing, its checks and log) and links to Edit or Delete it in Manage Clients (zGod itself never deletes). Fixed: suspending or switching a mailbox in zGod 100 stopped with a database error after the change was made (the panel's log keeps its time as a TIMESTAMP; zGod now leaves it to the database). The tab bar no longer shows small scroll arrows.
- Website and README: the Elk node is shown on every supported system (Ubuntu 26.04, Debian 13, AlmaLinux, Rocky Linux and RHEL 10, Fedora 45), not Ubuntu only; 35 ready-made dashboards (zGod's among them); a question on the Kibana dashboards page about adding a dashboard someone else made (sentora-elk-node dashboard install).
- Web Hardening 107: two new tabs. **Bans**: who fail2ban has banned now and why (SSH, mail, FTP, webmail, panel and phpMyAdmin logins, too many requests, by hand), since and until when, with Unban (out of every jail); ban an address by hand from every port (an hour, a day, a week, 30 days or until unbanned; never your own address, the server's or a never-ban one); a never-ban list (addresses and networks) that every jail keeps. **Flood protection**: off until switched on; an address sending more than the limit (300 a minute by default; pictures, styles, scripts and fonts not counted) to the websites is banned at the firewall for a while (fail2ban's sentora-flood jail on the websites' access logs, read from their end; a new website's log means a reload). **Slow attacks**: Apache's request timeouts (mod_reqtimeout, on by default on every system) shown. The daemon writes fail2ban's jail file, tests it with fail2ban's own check and puts the old one back when it fails; the page's requests run at once through the daemon. Tested with a fake fail2ban (67 checks), with the real fail2ban's own regex tool and settings test, and on real installed panels of all five systems (a real flood banned).
- Payment Plans 109 (a second review before real use): one payment start at a time per invoice (the invoice is claimed in one database step; two clicks or two tabs could otherwise make two Stripe checkout pages, the client pay the one the panel no longer knew, and be switched off later for an invoice they had paid); an answer about an older payment page (expired, declined) never wipes out a newer one; **Mark paid** closes an open online payment first, as Void did (a client could otherwise pay a bank-transferred invoice again by card); with the processor's keys removed, a Stripe checkout is not called closed until it has run out (a day); each plan keeps its billing day (a plan from the 31st is billed at every month's end, not on the 28th for good after February; yearly from Feb 29 comes back to Feb 29 in leap years); PayPal chargebacks: only an outcome that gave the money back counts as lost (all of a payment's disputes read); a reminder mail the server could not send shows on the invoice's history; no reminder for a deleted client; a plan stopped and started again can still switch off for its unpaid invoice; Stripe's idempotency key follows the payment start (a retried request makes no second page); the help for a restricted Stripe key names the read rights refunds and chargebacks need; on a phone every table is a column of small cards (nothing off the side). 231 tests, on SQLite and on MySQL 8.4 and MariaDB 10.11/11.8.
- Elk node: view-only Kibana logins for a kiosk or a colleague: `sentora-elk-node viewer add NAME` (prints the login and its password), `viewer password NAME`, `viewer remove NAME`, `viewer list`. A viewer opens every dashboard and reads the logs, and can not change, make or delete anything (Kibana's read privilege, the role sentora_viewer); Sentora's own logins (sentora-admin, elastic and the services') are never touched by it. Kibana asks a login again after 30 days (its session lifespan).
- Payment Plans 110: **test mode never surprises real clients**: billing all not-yet-billed clients at once while testing needs a tick saying they are real clients who get TEST invoices and can be switched off; **after a switch-off**, the seller chooses where a client who pays again is billed from: the day they pay (the default for new sellers: they had no hosting meanwhile) or where it stopped (the months off are owed; sellers from before keep this, as it worked); **a reminder some days before the due date** (3 by default for new sellers, 0 = none; once per invoice, not for one made in the last day); **Export (CSV)** of every invoice for the accounts (number, client, dates, net, tax, total, state, paid with, refunds and chargebacks; cells that would be spreadsheet formulas kept as text). 241 tests.
- Payment Plans 111: **the client's billing details** on their invoices (company, address, VAT or tax ID; the client fills them in on their Payment Plans page, from the next invoice on; an invoice keeps what it was made with); **extra lines and one-off invoices**: the seller adds lines (a setup fee, an extra mailbox, a discount below zero) to a client's next hosting invoice, or sends a one-off invoice at once with its own due date (paid online like any other, and unpaid past the grace days it switches the client off like any other; it never moves the paid-until date, and a client switched off is switched on again only when nothing else is overdue); waiting lines can be dropped before they are billed; an invoice shows its lines and a subtotal before the tax. 263 tests.
- Payment Plans 112: **PDF invoices and credit notes** (made by the panel itself, no extra program; a PDF button on every invoice, and the PDF goes with the invoice email and the paid email); **credit notes** for money given back: made by themselves when the daily check finds a refund or a lost chargeback at PayPal or Stripe, or by the seller for money given back another way (a bank transfer), numbered on their own (CN-), never more than the invoice, their tax in the same share; **tax options**: prices that include the tax (the invoice shows the tax in them), rates by the client's country (such as the EU's one-stop shop), and the reverse charge for a business client in another country that gives its VAT ID (no tax, the invoice says why); the client gives its country with its billing details; Export has what was credited. Fixed: an amount below zero (a discount) is written with one sign in the CSV and PDF; lines that went on a deleted test invoice wait for the next one again; every box on the settings form has its proper style. 311 tests.
- Docker Hosting nodes on AlmaLinux, Rocky, RHEL and Fedora: **Extra isolation (gVisor) now works with SELinux enforcing** (node agent 121). gVisor's sandbox runs in Sentora's own SELinux domain for it, built by the node's installer from container-selinux's own template (as container_t is), at the app's own level: one app's sandbox reaches none of another app's files or gVisor state, and beyond container_t it may only keep its own state and set itself up in its own private namespace (proven on a real AlmaLinux 10 with SELinux enforcing: Actions > gVisor SELinux probe). Until now those apps ran on the standard runtime there. Run `sentora-docker-node-update` on such a node; apps made before switch when next updated. The Docker node test now reads SELinux's refusals from audit.log itself (the tool it used is not on the AlmaLinux image, so it saw none) and checks the sandbox's domain and level.
- Log Forwarder 212: the Elk node's alerts are one notice at the top of the panel instead of one each. Closed, it stays closed while the same alerts go on (their figures change) or some clear, and comes back only when a new one starts. The new Alerts card on the Log Forwarder page lists what needs a look, each with **Mute** (an old test machine, a website only reachable inside), says per kind whether it comes as notice and mail, notice only or not at all, and lists what is muted with Unmute. The mail follows the same choices.
- Elk node: the website checks find your websites as your office does. Heartbeat (the checks) gets its own DNS and hosts files, for it alone: the DNS servers this server really has (Ubuntu's local helper, 127.0.0.53, does not pass .local names on to them, so internal websites looked "down"), or the ones chosen with `sentora-elk-node dns SERVER..` (or `dns panel`: the panel's own DNS). When the panel's address is an inside one, each website is checked at the panel's own address (an office network seldom reaches its own public address from inside, so public websites timed out); `sentora-elk-node sites-at auto|panel|dns|ADDRESS` changes it. A website no DNS knows (the office's, the system's, or the panel's own when checks go to the panel) and not in the node's /etc/hosts is not in use yet: it is left out of the checks, so it makes no "down" alert; `sentora-elk-node status` lists them.
- Elk node on every supported system: besides Ubuntu 26.04 it now installs on Debian 13, AlmaLinux / Rocky / RHEL 10 and Fedora 45 (Elastic's own apt or yum repository, its key checked; ufw or firewalld; SELinux stays enforcing, the four syslog ports labelled), and the certificates it makes carry key identifiers (Fedora's OpenSSL 4 left them out and strict TLS clients refused them). The whole Elk test (the panel's logs, every source, alerts, dashboards) passes on all five, and on a real AlmaLinux 10 machine with SELinux enforcing every source arrives with nothing refused (18 checks).
- Elk node, Active Directory: Windows' own accounts are no longer counted as people. Every session on a server logs its screen and font drivers on "at the keyboard" as DWM-1, UMFD-0 and so on; they filled the logon tables. The pipeline now marks them (and computer accounts ending in $, ANONYMOUS LOGON, LOCAL SERVICE and the other NT AUTHORITY accounts) as windows.system_account, and the people tables leave them out (by name as well, for events stored before). Real accounts, sclark's unlocks included, stay.
- Elk node, the online store: searches are sorted into customer searches, bot noise (WordPress probes such as wp admin and xmlrpc, one or two characters such as a and by, long random codes) and old addresses of the store (by model ..., view id ..., still asked for by search engines or old links). The store tables show customer searches only, visits count people only, a new table "Old addresses still being asked for" lists the old ones to redirect, and Magento's counts are labelled "since the store began" (Magento counts them that way). The Sales wall's latest orders show what was in each order. Log Forwarder 213 sends each order line with its order number and sends the store's orders and searches once more, so what is already on the node is sorted too.
- Windows: the native Windows work has its own repository, RusTus/sentora-windows-2027 (private for now). It starts with the Windows Server 2022/2025 installer: Apache, PHP 8.5, MySQL 8.4 and FTP (SFTPGo) into C:\zpanel. It asks about each part, with Yes as the default, and its own install test runs on a fresh Windows Server 2025 on every push.
- Windows (sentora-windows-2027): mail in the Windows installer: Stalwart (SMTP, IMAP, POP3, calendars and contacts), Roundcube webmail and ActiveSync for phones (Z-Push), over HTTPS only, with mailboxes through C:\zpanel\bin\mailuser.ps1. Tested on Windows Server 2025, ActiveSync as a phone would.
- Windows (sentora-windows-2027): ClamAV checks every mail message on Windows too (a virus is refused; while ClamAV is down mail waits and is not lost); tested with the EICAR test file on Windows Server 2025.
- Windows (sentora-windows-2027): DNS in the Windows installer: CoreDNS answers for your own zones (zone files in BIND's format, managed with C:\zpanel\bin\dnszone.ps1) and refuses every other name; tested on Windows Server 2025.
- Windows (sentora-windows-2027): Release 2027.2: ClamAV's first download no longer stops the install; the owner's own Server 2025 runs the whole stack (mail sent and received through webmail).
- Windows (sentora-windows-2027): Release 2027.3: updates with C:\zpanel\bin\sentora-update.ps1 (a nightly check that only tells; an update that keeps everything, with the answers given at install); tested by a real update on Windows Server 2025.
- zGod (add-on 100, administrators): the ZPanel classic written again for Sentora-2027: everything on the panel in one place across every reseller (the server's totals and charts, every account with its package, reseller, disk and bandwidth against its quotas, each reseller's clients, one account in full with its websites, databases, mailboxes, forwarders, FTP and cron), suspend an account or switch a mailbox off as the panel does, and a daily report by email. Safe by design (bound values, the form key, administrators only); the old service restarts are gone.
- Panel on Windows, step 1 (a preview, in sentora-windows-2027 with -WithPanel): a module runs on Windows only when its module.xml says `<windows>yes</windows>` (the database-only modules: clients, packages, MySQL, my account, settings, notices, FAQs and others); root jobs through bin/zsudo.bat and the service SentoraZsudo (a fixed list: restarting the Windows services, running the daemon); Apache as its own account, not LocalSystem. `sys_versions::IsWindows()` and `CanRun()`; nothing changes on Linux.
- Panel on Windows, step 2 proven (a probe, sentora-windows-2027): each hosting account's PHP as its own Windows account (php-cgi under NT SERVICE\SentoraPHP-<account>, three per account), walled off from the other accounts, the panel and the server; a key per account stops one account's PHP from asking another's to run its scripts (Windows Firewall does not filter connections inside the server). Not built into the installer yet.
- Panel on Windows, step 2 in the installer: bin\phpaccount.ps1 makes each hosting account's PHP its own Windows account (add, remove, list, repair), Apache passes every site in the account's folder to it with the account's key; a PHP file of no account is refused, and a site's .htaccess can not turn on the panel's own PHP, includes or CGI. Tested on Windows Server 2025, also after an update and a repair.
- Panel on Windows: every client gets its own PHP (its own Windows account) when it is made in the panel, and loses it when deleted (its files stay); the daemon keeps them in line. The Windows release now also carries install-web-stack.ps1: Apache, PHP and MySQL only.
- Panel on Windows: websites. A domain, subdomain or parked domain added in the panel gets its Apache site (in the panel's own file, after your httpd-vhosts.conf), its folder and welcome page, and a gentle Apache restart; its PHP runs as the client's own Windows account.
- The native Windows installer now lives in sentora-installers-2027 (windows/server, moved from sentora-windows-2027): each release runs its Windows Server test and carries sentora-windows-server.zip (install-zpanel-stack.ps1 with the panel, install-web-stack.ps1 with Apache, PHP and MySQL only) with the panel's version; the panel's zips and updates are checked against the SHA-256 GitHub keeps for each file.
- Release 2027.94: the Sentora panel natively on Windows Server as a preview (sentora-windows-server.zip on the installers release: clients, packages, MySQL, domains, subdomains and parked domains; each client's PHP as its own Windows account; root jobs through SentoraZsudo; Apache as its own account), and the Windows installer now released here with the panel's version.
